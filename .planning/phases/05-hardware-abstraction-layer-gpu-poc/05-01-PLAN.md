Purpose: Give future GPU/TPU implementations a swap point that requires no public API change. This plan builds the abstraction only — no hot paths are wired yet (that happens in 05-02).

    Create three new types under package numja.core (file paths above):

    (1) ComputeBackend.java — a public interface with exactly these 8 method signatures, mirroring ParallelOps statics (use java.util.function.DoubleBinaryOperator / DoubleUnaryOperator; no new dependency):
      - void elementwiseBinary(double[] a, double[] b, double[] out, DoubleBinaryOperator op)
      - void elementwiseUnary(double[] in, double[] out, DoubleUnaryOperator op)
      - void scalarBinary(double[] a, double scalar, double[] out, DoubleBinaryOperator op)
      - double sum(double[] data)

      - double max(double[] data)

    (matmul carries flattened raw arrays + dims so a future GPU backend reads raw data without DMatrixRMaj. It does NOT return NDArray — the caller owns NDArray allocation, matching ArrayOps.dot's shape.)

    (2) CpuThreadBackend.java — public final class implementing ComputeBackend, singleton via lazy-init holder:
      - public static CpuThreadBackend getInstance() returns the singleton.
      - elementwiseBinary / elementwiseUnary / scalarBinary / sum / prod / min / max each delegate DIRECTLY to the matching ParallelOps static (1:1 indirection — identical numerics, identical THRESHOLD gate, identical FJP path).
      - matmul(a, aRows, aCols, b, bRows, bCols, out) reimplements ArrayOps.dot on raw arrays:
          DMatrixRMaj ma = new DMatrixRMaj(aRows, aCols, true, a);
          DMatrixRMaj mb = new DMatrixRMaj(bRows, bCols, true, b);
          DMatrixRMaj mo = new DMatrixRMaj(aRows, bCols);
          CommonOps_DDRM.mult(ma, mb, mo);
          System.arraycopy(mo.data, 0, out, 0, aRows * bCols);
        (1:1 numeric equivalent of ArrayOps.dot using EJML on row-major double[] — do NOT change algorithm; risk R3 mandates exact copy.)
      - Do NOT expose ParallelOps test hooks (setThresholdForTesting / resetThresholdForTesting stay package-private in ParallelOps).

    (3) BackendSelector.java — public final class, no public fields:
      - public static final int THRESHOLD_GPU = 4_096_000; (declared per research; NOT used for any dispatch decision in Phase 5 — GPU path never auto-promoted).
      - private static volatile ComputeBackend active = CpuThreadBackend.getInstance();
      - public static ComputeBackend get() returns active.
      - public static void setBackend(String name): allowlist = {"cpu-thread"} only; override honored only when System.getProperty("numja.backend.allow") equals "true". Unknown name, or allow flag absent/false -> set active back to CpuThreadBackend.getInstance() and log a warning via System.err (do NOT throw). Matches research threat HW-01: name-based allowlist, no ClassLoader reflection for arbitrary class names.
      - Do NOT put the HW-02 size ceiling here — it lives in 05-02 where dispatch branches on n. BackendSelector owns only selection in 05-01.

    No public API change: adding package-level public types in numja.core does NOT alter NumJa.java / ArrayOps.java public static counts. Do NOT touch NumJa.java or ArrayOps.java.
